#include <iostream>
#include <string>
#include <memory>
#include <vector>

class Bill {
protected:
    std::string patient;
public:
    explicit Bill(const std::string& p) : patient(p) {}
    virtual ~Bill() = default;

    virtual double total() const = 0;       // TODO 1: pure virtual
    virtual std::string type() const { return "Bill"; }

    void print() const {
        std::cout << type() << ' ' << patient << ": " << total() << '\n';
    }
};

class OutPatient : public Bill {
    double consultation, tests;
public:
    OutPatient(const std::string& p, double c, double t)
        : Bill(p), consultation(c), tests(t) {}
    double total() const override { return consultation + tests; }
    std::string type() const override { return "OP"; }
};

class InPatient : public Bill {
    int days;
    double perDay, surgery;
public:
    InPatient(const std::string& p, int d, double rate, double s)
        : Bill(p), days(d), perDay(rate), surgery(s) {}
    double total() const override { return days * perDay + surgery; }
    std::string type() const override { return "IP"; }
};

int main() {
    std::vector<std::unique_ptr<Bill>> bills;
    bills.push_back(std::make_unique<OutPatient>("Ravi", 500, 1200));
    bills.push_back(std::make_unique<InPatient>("Meena", 3, 2500, 40000));

    double sum = 0;
    for (const auto& b : bills) {
        b->print();
        sum += b->total();
    }
    std::cout << "Total " << sum << '\n';
}

B1.2 COMPARISON WITH DESIGN
---------------------------
The implementation follows the design: Bill is an abstract base class; OutPatient
and InPatient override total() and type(); and main processes both through
Bill pointers. The raw new/delete array in the question was changed to
vector<unique_ptr<Bill>>. This is a safety improvement: objects are automatically
destroyed if an exception occurs, avoiding leaks. The billing formulas are unchanged.

B1.3 PROVE RUNTIME BINDING
--------------------------
If the declaration is changed to a non-virtual ordinary function, it cannot remain
pure virtual (= 0). For example, change it to:
    double total() const { return 0.0; }
and remove override from the derived declarations (or leave the derived functions
as hiding functions). Calls through Bill* now call Bill::total(), not the derived
calculation. The displayed totals become zero (and the sum becomes zero), assuming
the base implementation above. This demonstrates static binding.

If only the word 'virtual' is removed but '= 0' is retained, compilation fails:
a pure-specifier is not permitted on a non-virtual member function. Therefore,
to demonstrate changed dispatch, the base function must be made non-pure and
given a body.

B1.4 PROVE VIRTUAL DESTRUCTOR
-----------------------------
The base destructor is:
    virtual ~Bill() = default;

With virtual destructor, deleting a derived object through Bill* invokes the
derived destructor first and then Bill's destructor. Without virtual, deleting
a derived object through Bill* has undefined behaviour. AddressSanitizer may
report an invalid deletion / allocation-deallocation mismatch, or it may appear
to run without a diagnostic; absence of a report does NOT make it valid C++.

A simple destructor experiment:
    struct Bill { virtual double total() const = 0; virtual ~Bill() {
        std::cout << "Bill destroyed\n";
    }};
    struct OP : Bill { ~OP() { std::cout << "OP destroyed\n"; }
        double total() const override { return 1; } };
    int main() { Bill* p = new OP; delete p; }

With virtual destructor output:
OP destroyed
Bill destroyed
Remove virtual from ~Bill and run with:
g++ -std=c++17 -g -fsanitize=address -fno-omit-frame-pointer test.cpp -o test
./test
The behaviour is undefined; record the exact sanitizer output from your own compiler.
Do not claim that a clean run proves safety.

REMOVE VIRTUAL FROM total(): COMPILER RESULT
--------------------------------------------
Removing virtual but retaining '= 0' gives a compile-time error similar to:
'virtual' is not permitted here / cannot declare a non-virtual function pure.
Removing both virtual and '= 0' permits compilation only if a base function body
is supplied, but calls through Bill* use the base implementation.

ALTERNATIVE: TEMPLATES
----------------------
A template solution can process each concrete type in its own container:
    template<class T>
    double sumBills(const std::vector<T>& bills) {
        double s = 0;
        for (const T& b : bills) s += b.total();
        return s;
    }
Use vector<OutPatient> and vector<InPatient>, then call sumBills on each.
Each call is resolved at compile time and can be inlined; processing N bills is
O(N), with O(1) extra accumulator space (excluding the containers). Storage is
one container per type. The disadvantage is that a mixed single list is not
naturally represented: callers must maintain separate lists or use a common
runtime representation such as a variant or base pointer. Templates may also
increase executable code size through instantiation.

CONCLUSION
----------
Virtual total() provides runtime dispatch for heterogeneous bills. A virtual
destructor makes deletion through the base pointer safe. unique_ptr further
automates lifetime management.
