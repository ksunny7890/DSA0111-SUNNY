TASK A1 – DESIGN THE POLYMORPHIC BILL HIERARCHY

Object-Oriented Programming – Hospital Billing System

A1.1 – Identify the Common Interface (2 Marks)

Different hospital bills may calculate charges differently, but every
bill must provide a common set of operations.

Common data

billId – unique bill number.

patientId – identifier of the patient.

patientName – patient’s name.

billDate – date on which the bill is generated.

Common operations

Operation | Purpose

total() | Returns the final amount payable for the bill.

type() | Identifies the kind of bill.

print() | Displays the bill details.

These members form the common interface of an abstract base class named
Bill.

A1.2 – Design the Hierarchy (3 Marks)

Bill is abstract because it declares pure virtual functions.
OutPatientBill and InPatientBill inherit from Bill and override each
pure virtual function.

#include #include using namespace std;

class Bill { protected: int billId, patientId; string patientName,
billDate;

public: Bill(int b, int p, string n, string date) : billId(b),
patientId(p), patientName(n), billDate(date) {}

    virtual double total() const = 0;
    virtual string type() const = 0;
    virtual void print() const = 0;

    virtual ~Bill() noexcept = default;

};

class OutPatientBill : public Bill { double consultation, medicine;
public: OutPatientBill(int b, int p, string n, string date, double c,
double m) : Bill(b,p,n,date), consultation(c), medicine(m) {}

    double total() const override {
        return consultation + medicine;
    }
    string type() const override { return "OutPatient"; }
    void print() const override {
        cout << type() << " bill " << billId
             << ", patient " << patientName
             << ", total = " << total() << '\\n';
    }

};

class InPatientBill : public Bill { double roomCharge, treatmentCharge;
public: InPatientBill(int b, int p, string n, string date, double r,
double t) : Bill(b,p,n,date), roomCharge(r), treatmentCharge(t) {}

    double total() const override {
        return roomCharge + treatmentCharge;
    }
    string type() const override { return "InPatient"; }
    void print() const override {
        cout << type() << " bill " << billId
             << ", patient " << patientName
             << ", total = " << total() << '\\n';
    }

};

Notation: + means public and - means private/protected. The hollow

override the base declarations.

A1.3 – Process All Bills Together (2 Marks)

Pseudocode:

START Bill* bills[n] = {address of each bill object} dayTotal = 0

    FOR i = 0 TO n-1
        bills[i]->print()
        dayTotal = dayTotal + bills[i]->total()
    END FOR

    PRINT "Day's total = ", dayTotal

END

Each pointer may refer to any concrete Bill subtype. Virtual dispatch
selects the correct total() and print() implementation.

Alternative representation and complexity

An alternative is one Bill structure containing a type tag and fields
for every bill kind. A total() function uses switch(type) to select the
calculation.

struct BillRecord { int type; // 1 = outpatient, 2 = inpatient double
consultation, medicine; double roomCharge, treatmentCharge; };

double total(const BillRecord& b) { switch (b.type) { case 1: return
b.consultation + b.medicine; case 2: return b.roomCharge +
b.treatmentCharge; default: throw invalid_argument(“Unknown bill type”);
} }

Factor | Abstract base + virtual functions | Tagged structure + switch

Time for n bills | O(n); one virtual dispatch per bill | O(n); one
switch per bill

Space per bill | Common fields + subtype fields + typically a vptr | All
structure fields plus type tag, even if some are unused

Adding a bill type | Add a derived class; existing client loop stays
unchanged | Update structure, switch and related code

Design | Extensible and separates bill-specific behavior | Simple
initially, but switch can grow

Conclusion: Both approaches total n bills in O(n) time. Polymorphism
generally provides better extensibility and avoids central switch
statements.
